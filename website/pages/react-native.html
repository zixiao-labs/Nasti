React Native 支持

Nasti 可以将 React Native / Expo 项目打包为 Hermes / JavaScriptCore 兼容的 CJS bundle，替代 Metro bundler 的离线打包流程。内置 nasti:react-native 插件处理平台扩展名解析、静态资源 stub、 以及 react/react-native 生态的自动外部化。

适用场景： CI 离线打包、自定义构建流水线、或需要在 Rolldown 的极速 tree-shaking 下打出更小 bundle 的场景。日常开发仍推荐使用 Metro dev server（npx expo start）获得最佳 HMR 体验。

安装

npm install -D @nasti-toolchain/nasti

React Native 和 Expo 本身作为项目运行时依赖安装：

# 裸 React Native 项目
npm install react react-native

# 或使用 Expo
npx create-expo-app my-app

项目结构

my-rn-app/
├── index.ts               # AppRegistry 入口
├── App.tsx                # 根组件
├── src/
│   ├── screens/
│   │   ├── Home.tsx
│   │   ├── Home.ios.tsx   # iOS 平台专属版本
│   │   └── Home.android.tsx # Android 平台专属版本
│   └── components/
│       ├── Button.native.tsx # 通用 Native 版本
│       └── Button.tsx     # Web 回退版本
└── nasti.config.ts

配置

// nasti.config.ts
import { defineConfig } from '@nasti-toolchain/nasti'

export default defineConfig({
  target: 'react-native',

  reactNative: {
    platform: 'android',    // 'ios' | 'android'
    entry: 'index.ts',       // 相对项目根目录，默认自动检测
    external: [],           // 额外外部化的包（react/react-native 始终外部化）
  },

  build: {
    outDir: 'dist',
    minify: true,
    sourcemap: false,
  },
})

入口文件

// index.ts
import { AppRegistry } from 'react-native'
import App from './App'

AppRegistry.registerComponent('MyApp', () => App)
// App.tsx
import React from 'react'
import { View, Text, StyleSheet } from 'react-native'

export default function App() {
  return (
    <View style={styles.container}>
      <Text style={styles.title}>Hello from Nasti!</Text>
    </View>
  )
}

const styles = StyleSheet.create({
  container: { flex: 1, alignItems: 'center', justifyContent: 'center' },
  title: { fontSize: 24, fontWeight: 'bold' },
})

打包命令

# Android bundle（默认）
npx nasti react-native

# iOS bundle
npx nasti react-native --platform ios

# 简写别名
npx nasti rn --platform android

# 指定入口与输出目录
npx nasti rn --entry index.ts --outDir build

# 开发模式（保留 __DEV__ = true，不压缩）
npx nasti rn --mode development --no-minify

产物布局：

dist/
└── android.bundle   # CJS bundle，可直接加载到 Hermes / JSC
                     # iOS 构建时文件名为 ios.bundle
与 Metro 的关系： Nasti 生成的 bundle 格式与 npx react-native bundle 产物等价（CJS），可直接替换用于 EAS Build 的 jsBundleDir 或 Android 的 assets/ 目录。

平台扩展名解析

nasti:react-native 插件在解析相对路径时，按以下优先级查找文件：

  1. Button.{platform}.tsx（如 Button.ios.tsx）
  2. Button.native.tsx
  3. Button.tsx（通用回退）

所有 .tsx / .ts / .jsx / .js 扩展名均支持此逻辑。

// 代码中正常引入，Nasti 自动选择对应平台文件
import Button from './components/Button'
// platform=ios  → Button.ios.tsx（如存在）
// platform=android → Button.android.tsx（如存在）
// 均不存在      → Button.native.tsx → Button.tsx

静态资源

图片、字体等静态资源（.png、.jpg、.ttf 等）被替换为 轻量 stub 对象，避免打包时报错： 

// 源码中正常 import
import logo from './assets/logo.png'
// 打包后等价于：
// const logo = { uri: 'logo.png', width: 0, height: 0 }
注意： 生产场景下，图片资源通常由 Metro 的 asset 注册系统或 Expo 的 Asset.loadAsync 管理。Nasti bundle 中的 stub 保证代码不报错， 实际图片仍需通过原生端资源目录（android/app/src/main/assets/）提供。

外部化策略

以下包始终被标记为 external，不打入 bundle：

  • react
  • react-native 及所有 react-native/* 子路径
  • @react-native/*
  • @react-native-community/*
  • @react-navigation/*
  • expo 及所有 expo-* 包

通过 reactNative.external 可追加更多外部化包（如私有原生模块）： 

export default defineConfig({
  target: 'react-native',
  reactNative: {
    external: ['@my-company/native-camera', 'react-native-reanimated'],
  },
})

配置参考

选项类型默认值说明
platform'ios' | 'android''android'目标平台，决定扩展名优先级与产物文件名
entrystring'index.ts'入口文件，相对项目根目录；不存在时自动检测常见路径
externalstring[][]追加外部化的包（react/react-native 生态始终外部化）

编程式 API

import { buildReactNative } from '@nasti-toolchain/nasti'

// Android bundle
await buildReactNative({
  root: '.',
  reactNative: { platform: 'android' },
})

// iOS bundle
await buildReactNative({
  root: '.',
  reactNative: { platform: 'ios' },
  build: { sourcemap: true },
})

也可以直接在插件模式下使用 reactNativePlugin，集成进已有 Rolldown 流水线：

import { reactNativePlugin } from '@nasti-toolchain/nasti'
import { rolldown } from 'rolldown'

const bundle = await rolldown({
  input: 'index.ts',
  plugins: [
    reactNativePlugin(resolvedConfig),
    // 其他插件…
  ],
})

与 EAS Build 配合

在 Expo 托管工作流中，可用 Nasti 替换默认的 Metro bundle 步骤， 生成的 .bundle 文件通过 EAS 的 customBuildConfig 注入： 

// package.json
{
  "scripts": {
    "bundle:android": "nasti rn --platform android --outDir dist",
    "bundle:ios":     "nasti rn --platform ios --outDir dist"
  }
}
// eas.json（自定义构建步骤示例）
{
  "build": {
    "production": {
      "android": {
        "buildProfile": "production",
        "prebuildCommand": "npm run bundle:android"
      }
    }
  }
}
